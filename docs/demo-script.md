# 演示流程

## 演示前准备

1. 使用独立演示数据库和千问 Key，配置 `DEMO_SHARED_PASSWORD`。
2. 运行 `docker compose up -d --build`，确认 `/health` 返回数据库可用且 Checkpoint 已就绪。
3. 运行 `./scripts/seed-demo.ps1 -SharedPassword <演示密码>`，等待 Worker 完成提取任务。
4. 打开前端，确认记忆页中存在偏好、旧目标以及目标冲突候选。

## 3 至 5 分钟演示

1. 在会话 A 展示“先理解原理再看代码”的偏好与本周经历，展开运行详情查看五项召回分数。
2. 新建会话 B，询问“根据我的学习方式安排下一步”，展示跨会话个性化回答。
3. 打开长期记忆页，确认“优先参加秋招”的冲突候选，说明旧目标此时才变为 `superseded`。
4. 撤销确认或删除目标，再次提问，证明无效记忆不再进入召回。
5. 打开时间线，生成最近 7 天回顾；最后打开设置页展示模型、Token 预算和 Checkpoint 状态。

## 本机项目编码流程

项目编码入口的操作与验收状态见[阶段 4 记录](pre-desktop-stage4-agent-task-ui.md)。当前使用流程如下，完整真实模型与命令演示仍待验收：

1. 在实际加载的可信本机配置启用 `[local].enabled = true`，且 `[tools].enabled = true`，重启 API 后在设置页确认项目文件访问已启用。准备独立演示目录，勿使用实际工作项目测试撤销。
2. 新建对话，在输入框左下角“选择项目”中点击“添加本地项目…”，选择目录后自动添加并选中；普通聊天可不选项目。
3. 先让模型确认项目名称并读取演示 README，在运行详情核对真实文件读取事件，再发送编码任务。在对应回复内检查执行目录与完整命令，分别演示“批准本次”和“拒绝”；会话批准位于更多授权选项。
4. 展开命令输出查看失败/成功退出码，展开“修改了 N 个文件”查看 Diff 与撤销限制。原目录为默认模式，Worktree 位于项目菜单高级选项。
5. 运行中点击停止，检查后端终态；重新打开等待审批的会话，检查项目/执行目录与审批恢复，确认没有重复执行。发送后切换其他项目应开启新对话。

项目审计另验证超过 4 轮的多文件读取；项目默认预算为 24 轮，普通聊天保持 4 轮。测试触顶时在演示配置中临时降低项目预算，确认待调用工具未执行、回复保留已有文件发现并列出未检查范围，运行详情显示预算触顶事件；随后恢复配置并重启 API。

## 分层记忆检查

1. 在无项目的新对话发送“记住我偏好中文说明”，确认个人记忆页可见。
2. 选择项目 A，发送“记住项目测试约定使用 pytest”；新开同项目会话提问，检查召回事件同时允许个人与项目 A 的相关记忆。
3. 切换项目 B，发送“记住项目测试约定使用 vitest”；确认不会替换项目 A 的约定，也不召回项目 A 的私有事实。
4. 在记忆管理与时间线切换个人、A、B，分别检查列表、确认/删除/撤销与回顾范围。项目 A 执行一次普通诊断，确认不排队长期记忆提取；工具输出不自动出现在长期记忆中。
5. 可选：显式创建项目 A 的受管 worktree，在其中发送“查看我的记忆”，检查与原目录共享同一项目身份；清理 worktree 不删除项目记忆。只在独立演示仓库进行。

以上是手工复验步骤；本轮自动化证据、迁移方式和真实模型验证边界见[阶段 5 记录](pre-desktop-stage5-layered-memory.md)。
