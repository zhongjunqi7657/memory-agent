## 使用方式

1. 点击“新建对话”，在输入框左下角点击“选择项目”。菜单向上展开，可搜索已有项目。
2. 首次使用点击“添加本地项目…”，选择本机文件夹后自动以文件夹名称添加并选中，无需另填项目绑定表单。取消窗口不会创建项目；不支持原生窗口时，可展开“手动填写路径”作为备用。
3. 输入任务并发送。普通聊天可选择“不使用项目”；默认直接在原目录工作。首条消息前可自由切换项目，发送后项目和执行目录固定；切换到其他项目或普通聊天会开启新对话。若出现“本地文件访问未启用”，需在实际加载的本机配置中启用 `[local].enabled = true`，且 `[tools].enabled` 不能为 false，重启 API 后再试；设置页也显示该状态。
4. 命令或删除需要批准时，在对应回复内查看执行目录、完整命令/参数和限制，选择“批准本次”或“拒绝”。会话批准收在“更多授权选项”中。
5. 命令输出与退出码可展开查看，超时或截断明确标记。文件修改默认折叠为“修改了 N 个文件”，展开后逐文件查看 Diff；支持撤销时需再次确认，后端重新检查版本。
6. 运行中点击“停止任务”会请求后端取消，并等待运行结束；不会把断开 SSE 当作停止。若在运行 ID 返回前点击停止，会先记下取消意图，收到 ID 后发送取消请求。

侧栏不再提供独立“编码任务”页。聊天、记忆、时间线与设置保留现有入口和浅色风格，项目菜单采用紧凑列表、适中字重与轻分隔线。

## 项目历史与高级选项

重新打开历史会话时，从持久化会话/Run 恢复项目、原目录或 Worktree 配置、运行状态和事件。尚无最终助手消息的运行也会显示，等待中的审批可继续批准或拒绝；不会为了恢复而重新请求模型。运行中禁止切换项目或对话；重启后运行由既有后端逻辑标记中断，不自动续跑。

Worktree 收在项目菜单的“高级选项”。发送前可选择已有 Worktree，或以最新提交、当前已跟踪文件快照创建；当前界面不选择未跟踪文件，创建请求显式传入空列表，并展示未带入文件。带回原目录和清理均先预览，再以指纹确认；当前会话绑定的 Worktree 需新建对话后再选择清理，避免使当前会话目录失效。

Diff 使用任务基线与文件工具归属证据，不以 `git diff HEAD` 代替。执行过命令或外部工具时，不保证修改归属，界面禁止自动撤销并说明原因；Diff 截断、排除文件、冲突与不可恢复状态会明确展示。命令仍以本地用户权限运行，界面不提供操作系统级隔离。

## 2026-10-18：已选择项目却无法识别的修复

复现：选择项目后发送“审计本项目”，Run 已保存 `project_id` 和执行目录，但模型只收到通用学习伙伴提示，没有项目名称/路径；开发启动器还加载了缺少 `[local]` 节的原目录配置，默认关闭本地工具。因此模型询问“是哪一个项目”，同时该历史 Run 没有文件快照。

修复将项目名称、ID、项目目录、实际执行目录、执行模式和有效工具状态作为 JSON 数据放入每次模型请求的系统上下文，并计入上下文预留预算。项目文本和工具输出明确视为数据；只读审计先列举/读取文件，根据证据回答。继续旧会话即使未重新传项目 ID，也恢复绑定项目；新普通会话不继承项目。关闭本地工具或全局工具时，模型与界面均说明无法读取文件，而不是假装项目不存在；`/config` 补充非敏感的本地开关状态。

本机运行现使用当前 worktree 内不纳入 Git 的 `config.toml`，沿用已有业务配置并启用 `[local].enabled = true`；默认示例配置仍为关闭，不改用户的 `F:/memory-agent-demo/config.toml`。API 已重启，数据库与 Checkpoint 就绪。命令和删除继续经过原有审批；旧运行的回复和缺失快照不会被伪造或补写，需要重新发送任务。

新增真实数据库回归覆盖：工具启用时模型收到项目身份并实际读取临时 README；本地关闭/全局工具关闭时仍知道项目身份但没有本地工具；继续会话恢复与普通会话隔离。真实 Edge + Qwen 验证 Run `4b11486b-3235-4b7a-a6c9-94392b616c7b` 在“项目选择演示”中读取 README 并引用 `# Project selection demo`，最终 `completed`；事件中只有本地读取，没有命令/写入/删除，Diff 返回 200 且修改为空。证据为 `.runtime/project-recognition-evidence.json` 与 `.runtime/project-recognition-verified.png`，均为本地验证材料。

## 2026-10-18：项目审计过早达到工具上限的修复

用户实际项目 Run `13c1f81f-2360-485e-aa1f-f972ba146d15` 只执行了 4 轮（一轮列目录、三轮读取），即返回固定上限提示。原因是项目审计复用了普通聊天的 4 轮预算，且终止节点没有整理已获取的文件证据。

项目任务改用业务配置 `[agent].project_max_tool_rounds`，默认 24、允许 0—100；普通聊天继续使用 `max_tool_rounds`，默认 4。LangGraph 递归预算随有效轮次调整，设置页展示两个配置值。达到预算后所有待调用工具均不执行，以错误工具结果补齐消息协议，再由不绑定工具的模型整理已检查范围、文件证据与未检查部分。回复明确标记阶段性结果，持久化 `agent.tool_limit_reached` 事件；若模型仍请求工具或返回空内容，使用明确未完成的保底提示。命令/删除审批和目录限制继续生效。

新增回归覆盖 6 个真实临时模块的逐个读取，默认项目预算可以完成超过 4 轮的检查；显式预算为 3 时停止读取并报告剩余 3 个模块。另覆盖预算为 0 时不执行任何工具、触顶待调用不执行、总结使用已有结果及模型继续请求工具的保底行为。完整后端 246 项、前端 20 项通过。
