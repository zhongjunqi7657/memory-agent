## 测试发现与修复

新增 App 用例先复现了两个缺陷，修复前专项结果为 **2 failed、20 passed**，记录为 `.runtime/stage5-frontend-reproduction.log`。

1. 时间线原先仅比较项目 ID。个人→项目 A→个人之后，第一次个人请求仍会被接受，覆盖第二次个人请求的新内容。
2. 回顾原先只对成功结果比较范围，旧范围的失败和加载状态仍会更新当前界面。

新增 [`useScopedTimeline.ts`](../frontend/src/useScopedTimeline.ts) 集中管理时间线、回顾和各自的加载/错误状态。每次访问范围使用独立身份，同一范围的并发请求使用递增序号；成功与失败都必须同时匹配范围访问身份和最新序号。界面切换立即隐藏旧内容和旧错误，旧请求完成不会结束当前请求的加载状态。App 复用该模块，减少原组件内的请求状态逻辑。
