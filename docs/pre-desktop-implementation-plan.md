## 1. 已确认的产品与执行规则

- 定位为本地优先、具有长期记忆和工具执行能力的个人 AI 助理；编码是首个完整任务场景，不把产品限定为纯编码助手。
- 默认直接修改用户选中的目录。普通聊天、个人记忆和普通文件任务不要求 Git；只读分析不自动创建 worktree。
- 项目入口参照 Codex：对话输入框左下角选择、搜索或添加本地文件夹，自动命名并选中，无独立绑定表单。发送前可切换，发送后项目与执行目录固定；选择其他项目会新建对话，历史会话恢复原项目。
- 用户主动选择时才创建独立 Git worktree。起点支持当前分支最新提交，以及显式选择的未提交改动快照；非 Git 目录不能悄悄初始化 Git 来满足该选项。
- worktree、进程沙箱和审批是独立机制。本轮默认交付受控本地执行，不将能力校验、路径校验、命令审批或桌面窗口宣传成操作系统级沙箱。
- 文件读写限定用户授权的目录。命令默认审批，支持仅本次批准和明确命令规则的本次会话批准；越界、破坏性操作和 Git 推送另行审批。MCP 连接批准不等于批准所有工具调用。
- 原目录模式保留任务修改并展示 Diff、命令退出码和测试结果，不自动提交或推送。worktree 模式由用户决定保留或将结果带回原目录。
- 撤销只针对可证明归属于本次任务的修改；保留任务前已有改动，发现后续外部修改则提示冲突，不强制覆盖。
- 个人长期记忆、项目长期记忆和临时任务上下文分层。原目录和其 worktree 共享项目身份，项目细节不默认跨项目召回；密钥、令牌不进入长期记忆。
- 新增本地编码能力优先支持和验收 Windows 原生运行，不强制依赖 WSL 或 Docker；保留原有跨平台功能。
- 保留外置 PostgreSQL + pgvector，补齐连接配置、启动检查和迁移，不同时替换数据库或实现数据库安装分发。
- 本轮完善 MCP 客户端：stdio、Streamable HTTP、tools、resources、prompts、连接管理、鉴权、授权、超时、取消和错误展示。保留 legacy HTTP 接口；不新增标准 MCP 服务端，不宣称覆盖全部可选协议扩展。
- 不纳入浏览器自动化、多 Agent 协作、定时任务、桌面壳或安装包。既有文档中的多 Agent 路线属于后续规划，不作为本轮进入条件。

## 3. 开发边界与配置约束

- 环境变量存密钥、部署环境与运行时覆盖；配置文件存业务阈值、功能开关和第三方参数；代码常量存固定枚举和协议值。
- 项目、任务、批准记录、历史连接状态属于运行数据，不塞进环境变量或业务配置。
- 优先复用 ToolExecutor、MemoryService、MCP Manager 与现有事件协议，不建立第二套工具或记忆写入管线。
- 项目/worktree 生命周期建议放入 `app/workspace`；运行控制与本地子进程建议放入 `app/execution`；审批扩展既有 `app/permission`；文件/命令工具放入 `app/tools/builtin`。
- 本地启动管理与现有 `app/runtime.py` 的事件循环职责区分，不为了换桌面框架重写后端。
- 新数据库实体按领域拆分并保持 Alembic 能发现全部模型；只在任务涉及处拆分大文件，不做无关格式或架构重写。
- 前端按工作区、任务、审批、Diff、MCP 划分功能模块；请求、类型与视图分开，不把全部新增功能堆进 `App.tsx` 或 `api.ts`。
- 界面延续项目风格，文字清晰、适中字重、少卡片和阴影；不展示原始密钥、原始供应商异常或模型内部推理。

## 4. 分阶段实施与门禁

每一阶段先写边界/失败场景测试，再实现；专项测试、全部既有回归和受影响前端检查通过后，才进入下一阶段。遇到失败先定位和修复，不以跳过测试替代验收。

### 阶段 0：建立可复现基线

- 为当前独立 worktree 准备自身依赖，核对锁文件；不在用户原目录修改依赖或代码。
- 准备明确命名的隔离 PostgreSQL + pgvector 测试库，执行全部迁移；禁止测试误用开发数据库。
- 复验后端、Ruff、前端测试、TypeScript/生产构建和现有离线评测；记录版本、命令与环境。
- 核对旧英文提交的远端交付状态，不将本地提交误报为已推送；不自动合并 main 或创建 PR。

验收：后端完整回归含真实数据库，无关键测试跳过；前端测试及构建通过。既有 36 样本中的 4 条质量失败单独留档，不删除、不描述为全绿；新增能力不得扩大这些已知问题。

阶段 0 已于 2026-10-11 完成：后端 153 passed、无跳过，前端 4 passed、生产构建与离线基线一致性检查通过；复现脚本及环境/失败路径证据见 [阶段 0 验收记录](pre-desktop-stage0-baseline.md)。

### 阶段 1：项目、任务身份与运行控制

- 新增用户域内项目绑定、真实目录规范化、任务/Run 关联；普通聊天仍可不绑定项目。
- 增加任务执行模式，默认原目录；worktree 模式是显式选项，未完成对应能力时不得静默退回原目录。
- 复用 Run 事件并补齐等待审批、取消和中断等必要状态；短事务持久化事件，使运行期间可回放。
- 提供状态与取消入口，维护运行中的任务句柄；重启后旧运行标记中断，不自动续跑写入或恢复会话批准。
- 同一目录的冲突写入任务不并行执行，项目切换不改变已运行任务的目录绑定。

验收：用户域隔离、原目录默认、目录无效/不存在、Windows 大小写及链接路径、并发写入冲突、运行中事件可见、断线不等于取消、重启不重复执行均有测试。

### 阶段 2：审批与受控文件/命令执行

- 审批绑定实际工具调用、项目/任务、规范化目录、命令及参数；改变参数后旧批准不能复用，拒绝或过期不得执行。
- 会话批准只覆盖明确规则，不采用字符串前缀作为任意 Shell 放行依据；高风险操作始终走单独审批。
- 实现文件列举、读取、搜索、创建/编辑与必要删除，拒绝未授权路径、链接越界、凭据路径和不支持的文件类型；编辑保留换行并检查文件版本。
- 实现 Windows 原生命令执行，显式工作目录、受控环境、输出上限、超时、退出码与脱敏日志；取消及应用关闭时回收本任务子进程树。
- 命令可能执行项目脚本，并以本地用户权限运行；明确披露其不是系统级隔离。审批和敏感路径检查不能保证 Shell 无法访问目录外。
- 内置工具全部经过现有执行器；MCP 连接授权与工具调用授权分离，不直接把配置能力视为用户授予能力。

验收：拒绝时零副作用、批准不可替换参数/重放、权限失效、链接越界、外部修改冲突、输出截断、非零退出码、超时/取消及 Windows 子进程回收均通过真实进程或临时目录测试。

阶段 2 已于 2026-10-17 完成：后端 198 passed、无跳过，前端 6 passed、生产构建、迁移升级/回退/重升及离线基线一致性通过；本地执行默认关闭，正式审批界面留到阶段 4。证据和使用边界见[阶段 2 验收记录](pre-desktop-stage2-controlled-execution.md)。

### 阶段 3：任务 Diff、撤销与可选 worktree

- 在修改前取得基线，区分任务前已有改动、可归属任务的改动和无法确认归属的外部改动。不能用 `git diff HEAD` 冒充本次任务 Diff。
- 文件工具保存必要的前后版本与指纹；撤销前再次验证。重复编辑、新建和删除都需要覆盖；外部修改时停止安全撤销并提示冲突。
- 创建独立 worktree，记录基准提交；显式快照包含已跟踪修改，并明确选择未跟踪文件。默认不带入忽略文件、密钥和依赖，不对原目录执行 stash、自动 commit 或 reset。
- 用户确认后才能将 worktree 结果带回原目录；先检查原目录状态变化，避免覆盖已有修改。保留与清理也需保护未交付修改。
- 命令/MCP 产生的变更只有取得充分前后证据时才纳入可撤销集合。网络写入、进程外副作用及归属不明变更不承诺一键回滚，界面明确标记限制。

验收：使用真实临时 Git 仓库覆盖干净/脏目录、暂存与未暂存修改、未跟踪文件、两个起点、原目录不变、项目身份一致、带回冲突、撤销保护与清理保护；不以破坏性 Git 重置实现撤销。

阶段 3 已于 2026-10-18 完成：后端 226 passed、无跳过，前端 6 passed、生产构建、迁移升级/回退/重升及离线基线一致性通过。默认原目录、显式 worktree、任务基线 Diff、文件工具归属与安全撤销、带回和清理确认均有真实文件/Git/数据库证据。命令或 MCP 执行后保守停止自动撤销；正式操作界面留到阶段 4。接口、恢复边界与已知质量问题见[阶段 3 验收记录](pre-desktop-stage3-workspace-changes.md)。

### 阶段 4：Agent 编码闭环与任务界面

阶段 4 仍在开发验收中；对话式项目入口、回复内审批/命令输出、折叠 Diff 与等待审批恢复已接入。最新回归与尚待验证项见[阶段 4 验收记录](pre-desktop-stage4-agent-task-ui.md)。

- 将项目身份、执行目录、任务工具和授权注入 Agent，保持普通聊天与记忆命令兼容，不自动创建工作区。
- 项目绑定不能仅存于执行上下文：每次模型请求必须知道当前项目名称、ID、原目录/Worktree 实际执行目录及工具可用状态，并计入上下文预留。工具关闭时界面和模型都明确说明无法读取，不能假装未选择项目或已审计；继续会话恢复绑定，普通会话不继承项目。
- 产品提示调整为个人助理，按任务提供编码约束；文件与工具输出当作数据，不当作更高优先级指令。
- 普通聊天和项目任务使用独立工具轮次预算，业务配置默认分别为 4 和 24。触顶后不执行待调用工具，补齐未执行结果并使用不绑定工具的模型生成阶段性结论，列出已检查与未检查范围；持久化预算触顶事件，保留既有审批和取消边界。
- 每轮模型请求重新核算工具 Schema、个人/项目记忆、代码、工具输出和消息的上下文预算；保留限流、超时和明确错误终态。
- 前端以同一对话承载项目与编码任务，移除独立任务页。项目菜单向上展开，Worktree 放入高级选项；审批紧邻对应回复，默认提供“批准本次/拒绝”，会话批准折叠；修改默认显示“修改了 N 个文件”，展开后查看 Diff 与确认撤销。
- 实现命令输出/退出码、停止及 Worktree 带回/清理预览。等待审批期间可恢复显示，包括没有最终助手消息的运行；停止需请求后端并等待终态，不能用取消 SSE 代替后端停止。
- 阶段 1/2 的审批和状态接口在本阶段完成正式界面；此前通过 API/自动化测试验收，不提前对外演示未完成闭环。

验收：确定性模型测试覆盖读取→修改→测试失败→修正→测试通过；覆盖拒绝审批、用户取消、模型失败、工具轮次上限、超长工具输出、重连恢复和历史事件兼容。另在独立演示仓库验证真实界面及真实命令。

### 阶段 5：分层长期记忆

- 保留现有个人记忆；新增项目作用域，项目/worktree 使用稳定项目 ID，不以临时目录路径直接作为记忆身份。
- 将作用域传递到提取、检索、冲突候选、确认/撤销、Embedding 补偿和 Worker；不同项目不能互相替换或泄漏记忆。
- 编码任务的工具日志与临时尝试不自动成为长期记忆；明确稳定项目约定才走现有治理写入流程，不能绕过 MemoryService。
- 摘要、Checkpoint 和切换项目的会话上下文同样保持作用域边界，不能只在向量检索处过滤。

验收：个人记忆跨项目适用、项目记忆隔离、worktree 共用身份、临时内容不入库、秘密拒绝、跨作用域冲突/删除/Worker 不污染；迁移前后既有记忆行为回归通过。

### 阶段 6：MCP 客户端扩展

- 保留官方 SDK stdio 与 Windows 事件循环桥；新增 Streamable HTTP，不将 legacy `/v1/mcp/*` 当成标准 MCP HTTP 协议。
- 增加工具、资源和提示词的发现与使用；只调用服务器协商支持的能力，声明并测试不支持的可选能力，不新增对外标准服务端。
- 支持无鉴权、显式凭据以及受支持的 OAuth 授权流程；验证重定向、授权状态和过期/撤销行为，禁止静默降级为匿名调用或任意地址访问。
- 密钥通过环境变量/受保护凭据引用提供；OAuth 临时及刷新凭据作为秘密处理，不进入业务配置、长期记忆、事件或代码仓库。
- 提供连接创建/编辑、启停、状态、鉴权和授权界面；资源访问与提示词使用也经过权限审查，服务器提示词不能扩大本地权限。
- 更新会话工具快照与 UI 状态，断连有明确状态；不自动重试具有副作用的工具调用。重连不得重复执行先前批准的写入。
- 本轮不默认支持 sampling、elicitation 或其他可选双向能力；收到未协商请求时明确拒绝。旧 HTTP/SSE 兼容不作为新增默认传输。

验收：真实本地 stdio 与 HTTP fixture 覆盖握手、协商、tools/resources/prompts、鉴权、OAuth 状态与令牌脱敏、允许/拒绝、断线、超时、取消、连接关闭和兼容接口；至少验证官方 filesystem 与一个 HTTP Server 的互操作。
