# 桌面化前阶段 1：项目身份与运行控制

验收日期：2026-10-17。状态：通过阶段门禁，可进入阶段 2。完整产品验收仍须完成后续阶段。

## 交付行为

- 项目属于用户，保存规范化后的真实目录。相同用户重复绑定同一目录或其大小写、链接别名时复用项目身份，不初始化 Git。不存在、相对路径及文件路径被拒绝。
- 普通聊天可以不绑定项目。新会话可指定 `project_id`；已有会话继承绑定，不允许把已有会话切到另一项目，避免复用其他项目的摘要和 Checkpoint。切换项目应新建会话。
- `Run` 作为本阶段的任务身份，保存项目、执行模式及启动目录快照；同一会话只能运行一个任务。所有绑定目录的任务暂按可能写入处理，对相同目录及其父子目录保守互斥，也跨用户互斥。
- 默认执行模式为 `original`。`worktree` 会明确拒绝，不创建目录，不自动退回原目录；真实 worktree 能力在阶段 3 开发。
- 事件提交数据库后再发送给 SSE。运行开始、工具审计和中间事件可在执行中从独立数据库连接回放。助手消息、提取队列及完成事件在同一事务提交；完成持久化失败时一并回滚。
- 取消会传递到模型/工具任务，等待工具清理，回滚尚未提交的工具数据库操作，记录 `run.cancelled`，释放目录占用。重复取消不重复打断清理。此前已提交的工具操作不会伪装成已撤销。
- SSE 断线停止缓存响应，后台任务继续执行，重连可回放；断线不是取消。前端收到取消或中断终态会停止恢复轮询。
- 启动时把旧 `queued`、`running`、`waiting_approval` 标记为 `interrupted`，只追加一次终态事件，不重放执行。关闭先取消并等待运行任务，再关闭 MCP 和 Checkpoint。
- API 启动时取得数据库会话级 advisory lock；同一数据库第二个 API 实例在恢复任务前启动失败，避免把其他实例的活跃任务错误中断。锁使用独立 autocommit 连接，不长期占用事务。

## 接口

以下接口保留现有演示鉴权。`user_key` 是演示用户域标识，不是真实身份认证；本阶段不能作为开放公网的本机执行服务。

| 方法与路径 | 行为 |
| --- | --- |
| `POST /v1/projects` | 输入 `user_key`、`name`、绝对 `directory`，返回稳定项目 ID；重复绑定不修改已有名称 |
| `GET /v1/projects?user_key=...` | 仅返回对应用户的项目，默认 100 条、最多 200 条 |
| `POST /v1/chat`、`POST /v1/chat/stream` | 兼容已有请求，新增可选 `project_id` 与 `execution_mode`（默认 `original`） |
| `GET /v1/runs/{run_id}?user_key=...` | 返回会话、项目、执行目录、模式、状态和起止时间；不存在或不属于该用户时返回 404 |
| `POST /v1/runs/{run_id}/cancel?user_key=...` | 提交取消请求；`cancellation_requested=true` 代表已通知任务，终态以状态查询或事件为准；已结束时幂等返回 false |
| `GET /v1/runs/{run_id}/events` | 沿用 `after_sequence` 回放，可在运行期间调用 |

审批等待状态已加入持久化模型；实际审批流程在阶段 2 实现，正式项目/任务界面在阶段 4 实现。本阶段不新增文件、Shell 工具或操作系统沙箱。

## 模块与迁移

- `app/workspace`：目录解析、项目所有权和目录绑定。
- `app/execution`：任务句柄与互斥、持久化事件/终态、重启恢复、API 单实例租约。
- `app/persistence/projects.py`：项目实体；会话与 Run 增加可选关联，历史聊天不要求绑定。
- `0008_project_run_control`：新增项目表、运行目录/模式和三个状态；回退会把新增状态映射为 `failed`，移除项目关联及目录列。回退会丢失这些新字段，实际数据回退前必须备份。
- Agent 注入项目与运行目录到工具上下文，异步图使用模型的异步调用入口，保留同步图调用兼容性。
