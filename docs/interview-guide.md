# 面试问答

## 为什么长期记忆不等于聊天记录

聊天记录是完整审计事实，但不能全部塞入上下文。长期记忆是经过提取、风险判断、版本治理和召回排序的少量可复用事实；两者生命周期和查询目标不同。

## 为什么同时保留情景记忆和语义记忆

情景记忆描述带时间的经历和阶段，语义记忆描述较稳定的目标与偏好。分层后可以通过类型匹配和时间衰减避免把一次短期状态误当作稳定画像。

## 为什么模型不能直接写 active 记忆

模型负责把自然语言转成候选结构，代码负责秘密拦截、敏感度、置信度、冲突和状态转换。这样同一输入的治理结果可测试、可审计，也不会让 Prompt 变化绕过安全规则。

## 冲突如何保持一致

普通聊天抽取时会把 active 记忆清单交给模型，同时用 `canonical_key` 和候选声明做用户域内校验。冲突候选进入 `pending`；确认事务把旧记录改为 `superseded`，拒绝则旧记录继续有效，撤销会恢复成对状态。

## 为什么自动召回和工具检索并存

自动召回固定注入少量高相关记忆，保证常规回答低延迟；`search_memory` 和时间线工具只在模型判断信息不足时使用，避免每轮加载大量历史。所有工具调用都有结构化事件和循环上限。

## 混合召回如何降级

PostgreSQL 使用 pgvector HNSW 获取向量候选，再组合关键词、时间、重要度和类型得分。Embedding 不可用时，向量权重退出并归一化剩余权重；记忆文本先落库，Worker 的内容版本幂等任务后续补向量。

## 为什么不用 asyncio.create_task 做记忆提取

进程退出会丢失纯内存任务，也难以处理多 Worker 竞争。任务表提供幂等键、租约、重试时间和错误状态，`SKIP LOCKED` 让多个 Worker 安全领取不同任务。

## SSE 断开为什么不会重复运行

Agent Run 独立于响应迭代器继续执行，每个事件先写 `run_events` 再推送。客户端保存 `run_id + sequence`，断线后只重放后续事件，不重新提交聊天请求。

## Checkpoint 为什么不替代业务表

Checkpoint 是 LangGraph 的恢复快照，格式服务于编排；消息、运行、事件和记忆表服务于页面、治理、审计与评测。两类数据使用同一 PostgreSQL 实例但保持独立所有权。

## 如何证明系统确实“越聊越懂”

离线数据集固定提取、无关、推断、敏感、召回、冲突、删除和隔离场景，报告 Precision、Recall、冲突拦截率、删除残留率、跨用户泄漏率以及 Embedding 降级比例。每次修改 Prompt 或召回权重都复跑同一快照。
