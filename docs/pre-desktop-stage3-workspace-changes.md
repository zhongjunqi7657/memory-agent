## 实际交付行为

默认仍在绑定的原目录执行，不隐式创建 worktree。启用本地执行后，任务在工具调用前保存目录基线；普通目录无需 Git。任务 Diff 对比任务开始时的实际内容，包含用户已有的脏文件内容作为起点，不使用 `git diff HEAD` 代替任务 Diff。没有历史基线的旧任务返回 409，不伪造历史变更。

文件工具在写入或删除前提交持久化意图，执行后保存前后 SHA-256、内容与权限。重复编辑合并为同一文件的任务前/任务后记录；相对路径别名不会产生第二份归属记录。写入前校验快照容量，写入后验证观察内容与写入结果一致。新建、删除和编辑的撤销均重新校验当前版本，恢复原始 BOM/换行；不操作用户的 Git 暂存区，不自动 stash、commit 或 reset。

撤销只处理可证明由文件工具写入且当前仍匹配的记录。外部修改、未完成的写入意图、未完成的撤销等情况会拒绝覆盖。命令或 MCP 一旦获准进入执行，就保守标记整个任务存在外部执行，已记录文件变更也降为未确认，不能一键撤销。该标记不证明发生了副作用，只表示缺少足够的进程级归属证据。拒绝批准的调用不会因此取得可执行权限。

worktree 必须由用户先显式创建，再在聊天请求中选择其 ID；绑定项目 ID 保持不变。仅支持已存在、有提交、无合并冲突/链接条目/子模块的 Git 仓库根目录。非 Git 目录可继续使用原目录模式，不会自动初始化 Git。

| 起点 | 带入内容 | 原目录行为 |
| --- | --- | --- |
| `head` | 当前 HEAD 的文件内容 | 保留原目录暂存、未暂存和未跟踪内容 |
| `snapshot` | 当前已跟踪文件的实际内容、删除，以及显式选择的非忽略未跟踪文件；暂存版本单独保留在 worktree 索引 | 读取并复核原目录，不修改其文件或暂存区 |

两个起点均省略并报告受保护的凭据/依赖路径和含可识别秘密的已跟踪文件；显式选择含秘密、受保护或被忽略的未跟踪文件会被拒绝。`snapshot` 当前要求带入文件为大小限制内的 UTF-8 文本，不支持的编码/二进制会拒绝创建；`head` 可以物化已提交二进制资源，但不会承诺其文本 Diff 或撤销。创建过程直接物化 Git 对象，禁用 hooks/fsmonitor，不执行 checkout 过滤器，也不创建提交。

## 带回与清理

带回和清理均分为预览及明确确认两步，确认必须携带预览指纹和布尔值 `confirm: true`。它们属于用户接口，模型没有创建、带回或移除 worktree 的工具。

带回前复核原目录的 HEAD、暂存内容和文件状态；创建后原目录有变化则拒绝带回。HEAD 起点与脏原目录在同一文件上的内容不同时也拒绝覆盖。worktree 自身的提交或暂存区变化、秘密、不支持的文件变化及新增忽略文件均会阻止自动带回。通过时逐文件检查并写入原目录，保留原目录索引；支持文本新建、删除及新目录下的文本文件。父目录创建和文件操作沿用不跟随链接的句柄保护。

保留 worktree 的方式是不调用清理接口，应用不会在任务完成或失败后自动删除它。清理仅接受配置管理目录下、UUID 与仓库身份匹配的 worktree，且文件、HEAD、索引和全部忽略文件仍匹配创建基线或已交付状态。未交付修改、交付后变化及指纹失效都阻止清理。创建/带回/清理失败后保留 `interrupted` 等状态和现场，不自动递归删除或重试具有副作用的操作。

带回与撤销是逐文件执行，不是跨文件系统与数据库的原子事务。中断可能留下部分已完成文件；数据库保存完成列表/逐文件状态，后续自动操作会停止，需检查现场。目录互斥只约束本应用操作；文件版本/句柄检查不能将任意外部编辑器和命令变成受操作系统隔离的进程。

## 接口使用

全部接口沿用现有演示鉴权和 `user_key` 用户域；这不是完整的本机身份认证，阶段 7 前仅供可信本机测试。所有变更接口还要求 `[local].enabled = true`。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /v1/runs/{run_id}/changes?user_key=...` | 返回任务起点 Diff、归属、`undoable`、截断/排除信息和指纹 |
| `POST /v1/runs/{run_id}/undo?user_key=...` | 任务结束后，按指纹确认并尝试安全撤销；活动任务/冲突返回 409 |
| `POST /v1/projects/{project_id}/worktrees?user_key=...` | 创建，正文为 `{"start_mode":"snapshot","untracked_files":["notes.txt"]}`，或 `{"start_mode":"head"}` |
| `GET /v1/projects/{project_id}/worktrees?user_key=...` | 查询状态、路径、起点及省略文件；含历史已移除记录 |
| `GET /v1/worktrees/{id}/delivery?user_key=...` | 带回预览、冲突原因与指纹 |
| `POST /v1/worktrees/{id}/delivery?user_key=...` | 以确认请求体带回 |
| `GET /v1/worktrees/{id}/cleanup?user_key=...` | 清理预览、冲突原因与指纹 |
| `POST /v1/worktrees/{id}/cleanup?user_key=...` | 以确认请求体清理 |

三个确认接口均接收 `{"fingerprint":"实际预览返回的64位指纹","confirm":true}`。正文禁止额外字段；旧指纹、冲突和执行状态不满足条件返回 409，其他用户的对象返回 404。活动任务与目录操作复用同一目录互斥控制。

创建成功后，将 `worktree_id` 与 `execution_mode: "worktree"`、所属 `project_id` 一起交给既有 `/v1/chat` 或 `/v1/chat/stream`。省略模式仍使用原目录；传入不一致的模式/ID 会被拒绝。Run 查询返回实际执行目录与 worktree ID。

## 模块、配置和迁移

- `app/workspace/snapshots.py`：有界内容基线、Diff、版本比较和精确恢复。
- `app/workspace/journal.py`：持久化写入意图、归属判定和安全撤销。
- `app/workspace/git.py`：真实 Git 元数据读取与 worktree 起点物化。
- `app/workspace/worktrees.py`：应用管理路径、创建、交付、清理及状态保护。
- `app/api/workspaces.py`、`app/persistence/workspaces.py`：用户确认接口与持久化实体。
- `0010_workspace_changes`：新增 `task_snapshots`、`managed_worktrees` 及 Run 关联；实际数据库回退前须备份。

业务阈值放在 `[local]`：`max_snapshot_bytes` 默认 16 MiB，`max_diff_bytes` 默认 64 KiB，沿用单文件及遍历数量限制。超出基线容量会终止任务，不使用部分基线。Diff 截断不代表不存在其余变更，版本检查仍基于完整受支持内容。

快照存储在 PostgreSQL，安全文本以 base64 保存原始字节；base64 不属于加密，应按本地项目内容保护数据库。含可识别秘密的文本只保存指纹，不保存原文或展示 Diff；识别规则不保证发现未知形式的秘密。被排除的文件不会获得可恢复声明。

worktree 路径默认为应用仓库下 `.runtime/worktrees/{UUID}`，与启动时当前目录无关；可通过运行时覆盖 `APP_DATA_DIR` 指定其他应用数据目录。管理目录必须位于绑定项目外部；若绑定应用自身仓库，需将 `APP_DATA_DIR` 设到该仓库外。本地数据路径与启动认证最终在阶段 7 统一交付。
